# Requirements Matrix

Проект: AI-сервис для анализа организационной структуры и функций ДО и ПОСЛЕ реорганизации.

Источник требований — docs/case/case.txt. Статусы ниже основаны на принятой проверке application 1776156aef950eb04447b8557c5934e9a0d9bbd4. Final branch release/hackathon-final от 014fd46c2623aeaff6e4101e05f1b6709caf908b; application code идентичен, последующие изменения docs-only. ID тестов — трассировка требований, а не имена автоматизированных тестов. См. [QA summary](qa/release-final-summary.md).

Priority: MUST — обязательное требование; SHOULD — рекомендуемый технический механизм или правило QA; OPTIONAL — необязательная возможность. Owner обозначает предлагаемую ответственную роль, а не подтверждённое назначение участника. Участник №3 отвечает за requirements, QA, evaluation и README; владельцы реализации требуют согласования командой.

## 4. QA Rules

Обязательная цепочка прослеживаемости:

`Requirement → Implementation → Test → Result → Evidence`

- `Expected result != Actual result`: результаты synthetic/gold baseline и результаты фактического приложения должны храниться отдельно. Gold/expected данные нельзя передавать AI pipeline приложения как вход во время evaluation.
- Поддержка PDF/Word/Excel считается подтверждённой только для реально протестированных вариантов форматов; ограничения (например scanned PDF, legacy DOC/XLS) должны быть явно отражены в README и evaluation.

| ID | Requirement | Priority | Owner | Test ID | Status | Evidence |
| --- | --- | --- | --- | --- | --- | --- |
| QA-01 | Для проверяемого требования фиксировать связь с реализацией, тестом, результатом и доказательством. | MUST | Участник №3 — QA | T-Q01 | NOT RUN | Отдельная проверка не заявлена |
| QA-02 | Не присваивать PASS без воспроизводимого теста. | MUST | Участник №3 — QA | T-Q02 | NOT RUN | Отдельная проверка не заявлена |
| QA-03 | Не присваивать PASS без доказательства фактического результата. | MUST | Участник №3 — QA | T-Q03 | NOT RUN | Отдельная проверка не заявлена |
| QA-04 | Не придумывать результаты тестов, accuracy или pass rate. | MUST | Участник №3 — QA / evaluation | T-Q04 | NOT RUN | Отдельная проверка не заявлена |
| QA-05 | Не объявлять возможность реализованной без проверки. | MUST | Участник №3 — QA / README | T-Q05 | NOT RUN | Отдельная проверка не заявлена |
| QA-06 | Использовать заранее размеченные примеры с ожидаемыми результатами и источниками. | SHOULD | Участник №3 — QA; предметный эксперт | T-Q06 | NOT RUN | Отдельная проверка не заявлена |
| QA-07 | Проверять поведение при недостаточных или противоречивых документальных основаниях. | SHOULD | Участник №3 — QA | T-Q07 | NOT RUN | Отдельная проверка не заявлена |

- Implementation: путь к реализации и проверяемая версия кода; наличие строки в README само по себе не доказывает работоспособность.
- Test: ID из матрицы, предусловия, окружение, входные документы ДО/ПОСЛЕ, воспроизводимые шаги и ожидаемый результат. ID в этом файле не означает, что тест уже написан или выполнен.
- Result: фактический результат запуска с датой и версией кода. В текущей матрице все требования остаются TODO.
- Evidence: ссылка или путь к сохранённому артефакту проверки — входным данным, логу, отчёту или снимку интерфейса с достаточным контекстом для повторения теста.
- Для существенного вывода AI доказательство должно включать идентификатор и версию исходного документа, состояние ДО/ПОСЛЕ, подтверждающий фрагмент и локатор: страницу/пункт PDF, раздел/абзац DOCX либо лист/ячейку XLSX.
- Возможная потеря функции требует проверки функции в ДО и полноты доступного набора ПОСЛЕ; отсутствие совпадения само по себе не доказывает потерю. Ограничения входных данных должны быть явно отражены в результате анализа.
- Потенциальное дублирование или конфликт проверяются по подтверждающим фрагментам для каждой затронутой функции/роли; предположение нельзя выдавать за установленный факт.
- Accuracy и pass rate допустимы только после реального прогона с описанными набором данных, методом расчёта, числителем, знаменателем и ограничениями.
- Матрица и связанные артефакты проверки должны храниться в проекте, чтобы другой участник мог восстановить состояние QA без истории переписки.
